# 実運用（Go-Live）チェックリスト

現在のサイトは**デモモード**です。決済も実発送も行われません。
実運用へ移行する前に、以下の項目を確認・設定してください。

## 1. 決済（Stripe 等）

- [ ] 決済プロバイダーを選定する（Stripe / Shopify Payments / PayPal 等）
- [ ] Stripe（例）のアカウントを作成し、本番APIキーを取得する
- [ ] `NEXT_PUBLIC_` 公開キーとサーバー秘密キー（`STRIPE_SECRET_KEY`）を環境変数に設定する
- [ ] 注文フローにチェックアウト（Payment Intent / Checkout Session）を組み込む
  - 現状の `/api/orders` は金額をサーバー側で再計算してDBに保存するだけ
- [ ] 注文確定前に金額を決済プロバイダー側でも再検証する（価格改ざん防止）
- [ ] 決済成功後のみ注文を「確定」状態にする（Webhook連携）
- [ ] 返金・キャンセル・カード不備のフローを整備する
- [ ] テストモードでカード決済を一通り検証する

## 2. 実送料の設定

- [ ] 配送業者を選定する（日本郵便 国際エアパケット / EMS / 国際宅配便（DHL・FedEx・UPS等））
- [ ] 配送業者API（例: 日本郵便API、ShipEngine、EasyPost、Shippo）を選ぶか、手動の料金テーブルを整備する
- [ ] `src/data/shipping-config.ts` の料金を最新の公式レートに差し替える
  - 現在は `confirmedDate: 2026-11-25`・`150円/USD` 仮定・`provisional: true`
- [ ] 為替レートを実レート（当日）で扱う仕組みを入れる
- [ ] 送料の切り上げ/切り捨て・端数処理の方針を決める
- [ ] 複数配送先（米国以外）への拡張有無を決める

## 3. 商品重量の実測

- [ ] 各商品（未開封の小袋/瓶）の実重量を計測する
- [ ] `src/data/products.ts` の `packagingWeight` を実測値に差し替える
- [ ] `packagingWeightProvisional: true` を解除（または削除）する
- [ ] 梱包材（箱・緩衝材）の実重量を `shippingConfig.packagingWeightGrams` に反映する
- [ ] 箱詰め時の総重量が送料の重量帯と一致することを確認する

## 4. 管理画面の本番認証

- [ ] `ADMIN_PASSWORD` を強力な値に設定する（`admin` のままにしない）
- [ ] `SESSION_SECRET` を長いランダム文字列に設定する
- [ ] 必要なら多要素認証（MFA）やIP制限を追加する
- [ ] ログイン試行のレート制限・ブルートフォース対策を入れる
- [ ] 管理画面へのアクセスを監査ログに残す

## 5. ドメイン・HTTPS

- [ ] 独自ドメインを取得し、Vercel に接続する
- [ ] カスタムドメインのSSL/TLS（HTTPS）を有効化する
- [ ] `www` と ルートドメインのリダイレクトを設定する
- [ ] サイト名・メタデータ（`src/app/layout.tsx` 等）を正式なものに更新する

## 6. 法的・その他

- [ ] 食品の輸出入に関する規制・関税・表示義務（FDA、米国税関、アレルゲン表示）を確認する
- [ ] 利用規約・プライバシーポリシー・返品ポリシーを作成・掲載する
- [ ] 領収書・納品書・通関書類（コマーシャルインボイス等）を正式なものに整備する
- [ ] テスト注文・サンプル住所（`src/data/sample-address.ts`）を実運用向けに変更/削除する
- [ ] 「Demo store」表記（`src/lib/store-labels.ts`）を実運用向けに削除・変更する
- [ ] 注文確定メール・配送追跡通知を実装する
- [ ] エラーハンドリング・監視（Sentry等）・バックアップ（Neon/PostgreSQL）を整備する

## 完了条件（Go-Live）

- [ ] 実決済で注文→決済→確定まで通る
- [ ] 実送料が正しく計算・請求される
- [ ] 商品重量が実測済みで箱詰め指示書が正確
- [ ] 管理画面が本番認証で保護されている
- [ ] 独自ドメイン + HTTPS で公開されている
- [ ] デモ表記が残っていない
